SECURITY / FEATURE OVERVIEW

Protection built into the operating system.

Jaguar ROM is an Android 11-based custom ROM for seven OnePlus models. These features focus on user control, communications filtering, physical-access restrictions and system hardening.

Important security context. Jaguar's additional protections do not replace security fixes available in newer Android versions. Their effectiveness depends on the exact device, vendor firmware, patch level, configuration and threat model. This page describes intended functionality, not an independent security audit.

01 / PHYSICAL ACCESS

Enhanced Lockdown Mode

Jaguar extends Android's Lockdown Mode with additional restrictions designed to reduce exposure when someone has physical access to a device.

  • USB data restriction: blocks ADB and file transfer while retaining charging, including for computers previously authorized for ADB.
  • Application installation restriction: prevents app installation during lockdown.
  • Credential-encryption key eviction: removes access to credential-encrypted storage keys as part of the lockdown transition.

Key eviction is not necessarily equivalent to a fresh Before First Unlock (BFU) state. Data may remain in memory or caches, and guarantees must be verified for each supported build.

02 / COMMUNICATIONS

SMS and USSD protection

SMS Firewall

Filters six categories of SMS selected by the ROM's implementation.

Type-Zero SMS

Filters Type-Zero silent SMS at the Android software layer. This should not be interpreted as preventing all network signaling, reachability checks or modem-level responses.

USSD authorization

Restricts third-party applications from issuing USSD requests without user approval, while allowing designated trusted system callers.

03 / USER CONTROL

Privacy and installation controls

  • Toggle to restrict application access to the clipboard system-wide.
  • Quick Settings tile to clear clipboard contents.
  • Toggle to disable sharing system-wide.
  • Toggle to disable screen capture system-wide.
  • Toggle to block silent application installation.
  • Separate toggle to block all application installation.
  • Restrictions on installation of SafetyCore and Verifier applications.
  • Alternative captive-portal detection using Ubuntu and GNOME endpoints instead of Google's default endpoint.

Controls have distinct scopes; blocking one access path does not imply that every possible data-exfiltration technique is blocked.

04 / PLATFORM HARDENING

Encryption, boot and firmware protection

  • Non-default encryption parameters intended to increase the difficulty of certain attacks.
  • Read-only or mostly read-only protections applied to many kernel symbols.
  • Optional write-protection module for persist and selected firmware partitions.
  • Device-dependent bootloader relocking while retaining Magisk, using a custom signing arrangement.

Root access, bootloader relocking and firmware protection have important tradeoffs. Consult device-specific instructions before changing boot or firmware configuration.
